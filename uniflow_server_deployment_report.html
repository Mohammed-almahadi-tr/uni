1. Executive Summary: Server Count & Separation Rationale

To host the UniFlow Platform with high-demand extensions (BigBlueButton Virtual Classrooms, Virtual Programming Labs (VPL), Medical/Science Simulators, and AI Proctoring), an enterprise workload-separated topology is mandatory.

Total Required Nodes: Exactly 4 Dedicated Servers + S3 Object Storage
Why separate nodes? Video transcoding (WebRTC UDP), untrusted student code execution (VPL Jails), and financial/student database transactions have conflicting resource patterns. Isolating them prevents exam crashes, guarantees 99.9% uptime, and eliminates security leak vectors.

4. Phased Production Deployment Roadmap

Phase 1: Base Hardening & VPC
Provision Ubuntu nodes; configure SSH Ed25519 keys, UFW firewalls, Fail2ban brute-force defense, and private LAN network.
Phase 2: Database & PgBouncer
Install PostgreSQL 17 + PgBouncer on DB node. Setup dual roles (uniflow_app vs uniflow) and WAL-G automated S3 archiving.
Phase 3: UniFlow App Deployment
Deploy Next.js 16 standalone build under PM2. Run migrations and execute npm run db:check-roles to guarantee tenant RLS isolation.
Phase 4: BigBlueButton & Coturn
Deploy BBB 2.7+ with FreeSWITCH, Kurento/Mediasoup, Coturn STUN/TURN, and post-recording S3 auto-export scripts.
Phase 5: VPL Sandbox & Simulators
Install vpl-jail-system with cgroups CPU/memory quotas. Connect LTI 1.3 Advantage authentication for medical/science labs.
Phase 6: Edge Proxy & Monitoring
Deploy Nginx with TLS 1.3 + Cloudflare WAF. Configure Prometheus, Grafana, and Uptime Kuma for 24/7 alerting and health checks.

6. Mandatory Security & Production Invariants

Key Architecture Guarantees:
1. Database RLS: The application connects only via uniflow_app behind PgBouncer so Row-Level Security cannot be bypassed.
2. Jail Sandboxing: VPL executions operate under strictly isolated Linux cgroups with a 5s execution timeout and disabled networking.
3. Disaster Recovery: Point-in-time database WAL archiving + encrypted daily offsite S3 sync ensures zero data loss.
